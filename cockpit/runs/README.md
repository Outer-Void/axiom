# runs/

## Purpose

The `runs/` directory is **AXIOM’s operational logbook and flight recorder**.

This folder stores structured records of actions executed through **Overwatch**, including tool runs, terminal commands, and AI-assisted analyses. It exists to provide **traceability, reproducibility, and post-action insight**—not as temporary output or disposable logs.

This directory is intentionally present in the repository as a **placeholder**, but its contents are **not** meant to be version-controlled.

---

## What gets logged here

Each action executed through Overwatch creates a timestamped run directory under `runs/`, typically containing:

- **`output.log`**  
  Full stdout/stderr from the executed command or tool.

- **`metadata.json`**  
  Machine-readable context, such as:
  - execution mode (operate, terminal, cleanup, ai, etc.)
  - action or tool name
  - working directory at time of execution
  - exit code
  - platform (termux, linux, wsl, macos, etc.)
  - start/end timestamps

- **Optional artifacts**  
  Notes, AI summaries, diffs, or additional files generated by the action.

In addition, AI activity may write to a rolling log such as:

- **`ai_output.log`**  
  A continuous record of all gpt-4o-mini outputs and analysis events.

---

## Design philosophy

`runs/` exists to ensure that AXIOM:

- Never “forgets” what was executed
- Allows post-mortem analysis of failures
- Enables AI-assisted review and explanation
- Provides an audit trail for operational decisions

This folder is part of AXIOM’s **memory**, not its configuration.

---

## Version control

The `runs/` directory itself exists in the repository so its purpose is explicit, but **its contents should be ignored by git**.

Typical usage:

- The folder exists
- Files inside are created dynamically at runtime
- Users may archive or prune runs manually when desired

AXIOM will never automatically delete run data without explicit user action.
